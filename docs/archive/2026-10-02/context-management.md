## Resulting behavior

- Model-facing workspace excerpts use 320 characters and explicit current/historical source identities. Canonical 2,000-character projections and full source documents remain intact. Human edits, pins, exact text and named state are preserved. The workspace manifest supplies current-file authority.
- Completed large write/patch arguments become source-linked historical pointers. Superseded or repeated read pages become receipt pointers while the newest current page stays exact. OpenAI can project those completed observations directly; Claude starts a new chain at 8,000 redundant bytes and preserves unchanged signed prefixes. Full canonical calls/receipts remain saved. Existing read-before-edit, version checks and complete readback checks still apply.
- Bulk tool ingress bounds content excerpts to 1,600 characters and falls back to a receipt pointer above 12,000 bytes. Current workspace/guide pages retain their existing 8,000-character bounds. Continuation guard recovery also bounds workspace and inspection excerpts, with explicit next offsets and original receipt retrieval.
- Settled named state/pins/exact text precede older material and the recent tail. Changing revision/protection metadata follows the tail. The last eight matching answer usages select a Claude settled-prefix breakpoint when cache writes exceed reads; otherwise growing-tail automatic caching remains, alongside the fixed system breakpoint. This is a heuristic, not a measured cache improvement.
- Economic reviews retain dated public-rate valuations, unpriced-call counts, coverage, local removable tokens and a bounded one-to-four-call horizon. An economic-only review requires projected carry to exceed selection + rewrite + retrieval + cache rebuild by 25%. Retrieval includes excerpt carry and observed reranking inference. Rewrite estimates need prior matching-model observations; missing cache buckets/rates prevent that trigger. Conservative tier/TTL rebuild costs are included. Pressure, periodic and explicit compaction continue to work.
- Jev can rerank at most six lexical source candidates (configurable maximum twelve) and classify a document's first 600 characters. Payloads must fit its byte cap; strict coverage/distribution validation and confidence gating apply. Confident positive retrieval matches can move ahead of uncertain candidates, whose relative order stays deterministic. No positive evidence, provider errors or malformed/oversized judgments fall back. Classification controls only bounded excerpts, preserves a lexical task match, and never creates confirmed state. Large chat attachments can use classification; agent attachments keep deterministic ingress within their existing limits.
- Narrow judgments require known exact rates and a conservative delegation gate. Its comparison is against an extra task-model judgment, not against zero-cost deterministic selection. Same-query/source/version/adapter assessments are cached in conversation events across service instances. Jev only ranks/classifies; the main model retains tool work, calculation, editing and completion authority. Delegated requests do not replace task-request links on subsequent tool receipts.

## Real Jev comparison

The opt-in [evaluation script](../../../scripts/evaluate-jev-delegation.js) sends only synthetic text. Two retrieval cases put a relevant original source behind five equally matching speculative drafts; deterministic lexical top four misses both. Two ingress cases contain a reported capacity constraint and an unresolved destination question. No task-model inference, personal-history transmission, live database mutation or artifact-writing delegation is used.

The [saved live record](jev-delegation-live.json) contains four complete request/response pairs from reported model `jev-1.13.0`. Jev returned the original code source with high confidence and correctly classified both ingress cases. The first gate rejected the capacity rerank because the distractors were uncertain, even though the actual correction was confidently direct. The gate was amended to avoid down-ranking uncertain sources while permitting a confident positive match to move ahead. [Offline replay of the same real answers](jev-delegation-replay.json), with zero additional inference, ranks the correct source first in both retrieval cases. Deterministic selection remains the baseline and fallback. Neither classification promoted data into named state; full source text remained exact.

Recorded Jev usage totals **$0.000147924** at the repository's October 2 public-rate snapshot. Deterministic selection uses zero inference calls. An initial four-call run completed inference but its exporter failed by assuming a nonexistent SQLite conversations table; those responses were not saved and their usage/cost is unknown. The corrected run records its four calls. Thus eight calls were attempted overall; the quoted valuation covers only the saved four, not the full work-session bill.

These are four hand-authored cases, not a blinded benchmark, matched long-task trial, or proof of general retrieval, quality or cost superiority. The final reranking rule was replayed against real answers, not sent as a new live evaluation. General completion, corrected decisions, numerical intermediates, current-version precedence under long trajectories, output exhaustion and total-cost trials remain pending.
