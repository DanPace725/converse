# Conversation memory repairs, 2026-10-05

The supplied Introduction to Assistant Capabilities export completed 28 turns, but automatic memory missed the corrected octopus budget, attendance, station count and accessibility requirement. Astra candidate extraction rejected reasoning effort none. Routine keep-working instructions became binding memories. Identical fields from two named projects shared heads, and the final activation primarily contained earlier research instead of current octopus requirements. Named state and verbatim context enabled the correct answers; this was not evidence that automatic memory worked correctly.

## Implemented

- Astra uses its observed supported reasoning levels, starting at low for extraction, through the shared engine/browser capability table.
- Memory policy v6 deterministically captures clear declared budgets, attendance, ages, durations, station counts, accessibility and offline requirements. Exact source spans and qualifications remain authoritative; multiline code fences are fully masked.
- Correction headers apply to substantive later clauses. A unique unconditional scalar field can supersede its earlier value inside the same project. Named/conditional/ambiguous budgets retain the previous conservative matching rules.
- Explicit project declarations, return instructions and scoped corrections define conversation-local project boundaries. Identical values in different projects have separate heads; activation selects the current project's records and global binding constraints.
- Legacy nonbinding records derive project scope only when their source references agree. Ambiguous merged records remain inspectable but are excluded from activation. Existing global binding records remain eligible. Missing old captures are not silently rewritten or backfilled.
- Keep working/developing and routine final-plan/audit requests are excluded from durable instructions. Clearly unapproved participant proposals retain their cost and approval qualifier as unresolved questions. Zero eligible passages do not consume the per-turn extraction allowance.

The default remains task-model extraction plus Jev shadow. Hybrid selection is still opt-in. No embedding/database migration is required; project scope uses the existing generic event envelope. Model-created named-state phase entries are not rewritten by this repair.
